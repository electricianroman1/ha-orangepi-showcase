# Telegram-бот «Умный дом»

Пакет Home Assistant [`bot/telegram_menu.yaml`](../bot/telegram_menu.yaml) (~950 строк): меню `/menu` с кнопками, разделы, уведомления, счётчики воды, включение ПК по Wake-on-LAN. Секреты вынесены в `secrets.yaml`, пример: [`bot/secrets.example.yaml`](../bot/secrets.example.yaml).

## Возможности
- Главный экран со сводкой, оформленные разделы, графики (`script.tg_chart` → shell_command → [`bot/tg_chart.py`](../bot/tg_chart.py), Pillow).
- Две роли: админ видит всё, остальные разрешённые чаты видят свои разделы и получают только уведомления о протечке и напоминание о передаче показаний воды (20-го числа в 10:00).
- Постоянная reply-клавиатура по ролям, кнопки «копировать» через прямой вызов Bot API (`rest_command.tg_api`).
- Раздел «Компьютер»: Wake-on-LAN и состояние по ping.

## Надёжная отправка
Провайдер рвал часть соединений с `api.telegram.org`, поэтому все сообщения идут через `script.tg_send`: до 3 попыток, успех подтверждается событием `tg_sent`. После двух неудач скрипт перезагружает запись интеграции бота: клиент зависал на мёртвом keep-alive.

## Грабли
- **Входящий polling может молча зависать** при рабочей отправке. Решение: сторож `tg_watchdog` каждые 10 минут проверяет `getWebhookInfo`, и если `pending_update_count > 0` дважды с паузой 90 с, перезагружает запись.
- **Не оборачивайте `send_photo` в repeat/until с `response_variable`**: зациклилось и отправило около 50 фото.
- **Токен утекает через логи.** `rest_command` пишет полный URL при ошибке, а в URL токен бота. Логгер `homeassistant.components.rest_command` выставлен в `error`. Если токен всё же утёк, сделайте `/revoke` в @BotFather и обновите `tg_api_url` в `secrets.yaml`.
- Новый чат нужно добавить ещё и в «Разрешённые чаты» интеграции Telegram, иначе бот его игнорирует.
- Для `api.telegram.org` может понадобиться обход блокировки на роутере.
